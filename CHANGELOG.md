## [Unreleased]
- docs: the fine-tuning anchor did not replicate, and the line stops — decision D11: seeds 43 and 44 at 10,000 rows on `uslapseagent`, with seed 43 clearing all three rungs (ΔAUC +0.0031/+0.0050/+0.0057, intervals excluding zero) and seed 44 clearing none (ΔAUC +0.0009/+0.0013/+0.0010, intervals including zero). Both seeds were required, so the anchor fails; the redirect is calibration, preprocessing and model selection. Evidence committed at `results/20261031T021845Z/`
- feat: the launcher checks the account balance before renting — issue #348: `MIN_CREDIT_USD` (default $1) refuses before `create`, `WARN_CREDIT_USD` (default $2) warns and continues, an unreadable balance warns rather than assuming, and `credit_before_usd` is recorded in the run ledger. The price ceiling bounds the rate; this bounds the balance
- docs: the paid path gains dispatch vocabulary — issue #247: `GLOSSARY.md` defines **dispatch** (the seam that builds and validates one command document before spend), **command document** (the versioned JSON sent to the box; no secret, no machine identity) and **ad-hoc run** (no declared experiment, explicitly recorded as such)
- fix: the model pin passes a path, never a label — issue #285 (reopened): `explicit_model_path()` distinguishes "an operator chose" from "the baseline label", and the launcher passes `model_path` only when one was set. The first attempt passed `v3_default`, which is a label, not a filename: the 2026-10-31 smoke failed every arm in three seconds with "Model v3_default not found in available models". With nothing set the library default applies and the record says `version: auto`, `version_source: auto`
- fix: a retry is a new attempt under one launch id — issue #326: `lease.sh` no longer clears `LEASE_LAUNCH_ID`/`LEASE_ATTEMPT` when the retry re-exec sources it, so `lease_begin` reuses the launch id and appends an attempt to the same record. The record now carries an `attempts` array with each attempt's instance id, state, outcome and timestamps; the top-level fields describe the current attempt. `retry_or_die` exports the id and the next attempt number before `exec`; `--max-attempts` still bounds total attempts, and a release never consumes one. The mock gained per-attempt instance ids and status sequences so the launcher-level retry is tested: one lease file, one launch id, two instances, both released. Adoption (#327) and the watchdog (#328) remain out
- feat: the paid-run launcher holds a lease — issue #325: before provisioning, `vast_run.sh` mints a launch id (`<utc>-<6 hex>`) and writes a lease record under `outputs/gpu-pilot/leases/`; the id is the provider label. One `lease_release` owns teardown from the EXIT trap and the retry path, returns `released`, `already_gone` or `failed:<reason>`, and is idempotent. A failed destroy keeps the instance id, prints the launch id and a one-line destroy command, and exits non-zero; an already-gone instance is mapped to `already_gone` rather than a false billing warning. A retry is refused unless release confirms the instance is gone. `--keep` records the instance as still acquired, not released. Records are runtime artifacts, not committed. Adoption (#327), retry identity (#326) and the watchdog (#328) stay out of this slice
- chore: the evidence trees are guarded — a new `evidence` check in `scripts/check.sh` (and a CI job) fails when a branch changes `outputs/` or `results/`, unless the pull request carries the `evidence-change` label or the run sets `EVIDENCE_CHANGE_OK=1`. Raised by the 2026-10-30 retro, after a commit deleted seven tracked logs while its own plan asserted the diff was empty. Also adds a coding standard for cost and availability claims, and three AGENTS.md traps
- feat: the pilot takes its experiment from the registry — issue #238: `experiments.toml` gains `[pilot_methods.<id>]` (an arm and its epoch budget) and `[pilot_experiments.<id>]` (dataset, arms, seed, folds, row sizes, model version and a complete base config), with four declarations reproducing the committed pilot metrics. `run_pilot.py --experiment <id>` supplies every value; the registry-owned flags default to `None`, a flag that repeats the declaration is accepted, one that contradicts it is refused naming the experiment and the flag, `--arms` selects within a declaration, and a run without an id behaves exactly as before. `arm_epochs()` reads the declared budgets, so the ladder no longer comes from code when an experiment is named. Arm records move to schema 4 with an optional `provenance.experiment = {id, declared, resolved}` (ADR 0004) and v3 records still read; the paid-run launcher takes `--experiment` and refuses the old dataset/size triple beside it
- feat: the remaining producers and analysis scripts read the registry — issue #235: `run_tuned_baselines`, `run_tabfm`, `run_reframe_frequency` and the home-turf sweep take their datasets from `experiments.toml`; `analyze_pr_auc`, `analyze_tuned_baselines`, `plot_money_chart` and `rescore_altmetrics` take dataset names/files and method sets from it. The frontier's `DATASETS`/`REG_DATASETS` constants are gone; both modes select from the registry. Metadata is unchanged, so the committed seed-42 outputs are unchanged by construction; `tests/test_registry_producers.py` pins every file/target/drop/metric/transform and each script's selection. Tuned variants and TabFM remain local method studies, not experiments, and the pilot cache rescore is out of scope
- fix: the pilot pins the model it records — issue #285: `run_arm_a_raw` now passes `model_path=resolve_model_path()`, and the fine-tuned arm forwards the same pin through `extra_classifier_kwargs`. Until now the record stated the resolver's label while the library loaded its own default, so a run with `TABPFN_MODEL_PATH` set recorded a model it did not load. With the variable unset — every run to date — the loaded weights are the same baseline, so results are unchanged
- fix: the pilot pins the model it records — issue #285: `run_arm_a_raw` passes `model_path=pinned_model_path()` and the fine-tuned arm forwards the same value through `extra_classifier_kwargs`; the record now says `version_source: pinned` rather than `resolver`, because the value it states is the one it asked for. This can change what loads: the library default is `auto`, and `docs/MODEL_VERSIONS.md` records that the server default became v3.5, so an unpinned call no longer resolves to v3. Pilot results are therefore pinned from this commit on; the anchor re-baselines in every run (D9), so a version change is absorbed by its in-run `A_raw` rather than compared across eras
- chore: retire the notebook-era configuration module — issue #234: `src/baseline_config.py` claimed to own experiment configuration but described the v2-era pipeline and was read by only the notebook-era loader and two smoke assertions. `DATA_DIR` (from the repo layout), `RANDOM_SEED = 42` and `set_random_seeds()` now live in `src/baseline_utils.py`, which the notebook-era code already imports; `data_loader_class` and the four notebooks that imported the old module use that source. The module and its smoke assertions are deleted, not disabled, and nothing imports it
- feat: D1 profiles the anchor datasets and the whole design table — issue #302: `--all-anchors` and `--dataset NAME` resolve through the pilot's own registry, one record directory per dataset, with a pre-flight that refuses before writing if any file is missing; the profile gains per-column missingness, target quantiles, the numeric-to-categorical ratio and a bounded VIF beside the maximum pairwise correlation (refused with a stated reason when it cannot be computed). The missingness pattern is deliberately not labelled: MCAR/MAR/MNAR needs a test the profile cannot run. No committed record changes

- feat: the row-size axis is declared in the registry — issue #264: an experiment may declare `row_sizes`, and full is always a point, so `[1000, 5000]` means 1 000, 5 000 and the whole table while declaring none means full only. `resolve_row_size()` refuses a point the declaration does not contain, naming the experiment and what it declares, before anything is fitted. The frontier runner gains `--size full|N` (refused with `--data`, with `--pr-auc` whose append-only ledger has no column for the point, and on the regression path until #235); the point is stamped in the run manifest, the capture manifest and every results row, a non-full point joins the output and capture filenames so two points cannot overwrite each other, and the plot title names it instead of asserting `full`. `slice_data` moves to `src/row_sizes.py` so the frontier and the size sweep choose the same rows for the same declared size; the sweep now reads its sizes from the registry instead of its own constant, and its committed `(dataset, n_rows)` cells are unchanged
- fix: reuse a sweep row only when its provenance matches — issue #233: the frontier reused a `home_turf_sweep_results.csv` row on dataset, row count and an empty `n_estimators` alone, so a seed-7 run could take a seed-42 split row and a run under one TabPFN version could take another's. The sweep writer now stamps `seed` and the resolved `model_version` on every row, and `reusable_sweep_rows` requires both to match the run before a row may stand in for a fit. A table without those columns — the committed 220 rows — is never reused. The frontier only reads the sweep table, so until the sweep writer is re-run (a paid hosted sweep) every classification run refits everything, including the hosted TabPFN rows; reuse resumes once the table carries attributable rows. That spend is the user's call and was not run here. The run manifest now records, per dataset, which methods reused a row and which were fitted. The legacy rows are not rewritten
- feat: a run records its declared and resolved model version — issue #239: the run manifest and the capture manifest now carry `model_version_declared` beside `model_version` (what execution resolved) and `model_version_mismatch` (`true`/`false`/`null`), built by one helper from the declarations the artifact covers, so the two cannot disagree. The run manifest covers every experiment the run will execute: it names a literal when they agree on one, and flags drift when any of them differs — so the default sweep, not just `--experiment`, can contradict itself. A capture takes its own dataset's `Experiment`, so it never says "no experiment declared this" about a declaration that exists. A mismatch is **recorded, not enforced**: #233 owns the reuse predicate and needs exactly `false` to reuse a row, while `null` (an ad-hoc `--data` run, or a filter that covers nothing) is an absence and never a pass. The resolver's env-first order and the registry's literal-only load are unchanged
- fix: regression runs honour their seed — issue #232: `--seed 7` used to build folds with `random_state=42` while the filename, run manifest and capture manifest all said 7. `run_dataset_regression` now takes the run's seed and fold count and passes both to the shared `make_folds("kfold", n_folds, seed)`; `--experiment` uses the declaration's values; the CLI paths use `--seed` and the default fold count. The capture's `split` string now says `KFold(..., random_state=<seed>)` instead of the hardcoded 42, and every `N_FOLDS` use inside the path follows the declared count. Seed 42 is unchanged: the canonical split is pinned against a stored hash of the pre-change fold indices, and no computation moved. Methods still come from the code list until #235; a full seed-42 CSV reproduction needs the hosted TabPFN step and is not claimed
- fix: a mock launch's log stays out of the working tree — issue #280: `vast_run.sh`'s `cleanup()` fetched the container log into a hardcoded `$REPO_DIR/outputs/gpu-pilot/logs`, so every mock launch in `pytest tests/ -q` left logs in the directory the runbook treats as the record of paid launches (`outputs/gpu-pilot/logs/**` is deliberately kept by `.gitignore`). The log now lands under `$OUTDIR/logs`, beside the launch's record and ledger, so `VAST_OUTDIR` isolates a mock launch completely; a real launch's default path is unchanged, and the suite pins both halves — the mock's placement behaviourally, in the existing full-path launch, and the default by evaluating the launcher's own `OUTDIR`/`LOG_DIR` lines
- feat: frontier classification reads its experiment — issue #231: the classification frontier stops reading its dataset list, method lists, metric fallback and fold constructor from code. `experiments.toml` decides the dataset, the compared methods (in declared order, hosted TabPFN last), the metric and the folds; `src/experiment_spec.make_folds(kind, n_folds, seed)` is the one splitter for both modes. Methods dispatch through a code-side table keyed by the declared id — a method the file names but the code cannot build fails at selection, and an unknown metric name raises instead of falling back to log loss. The all-datasets path keeps the CLI `--seed` so split-stability runs still fold at that seed; `--experiment` uses the declaration's seed and fold count. No computation changes: the same `coil2000` command on the pre-change tree is bit-identical on every shared column. Output filenames and capture stems are unchanged. The `DATASETS` constant stays only for `run_tuned_baselines` until #235
- feat: record contract — issue #241: a pilot arm record now declares `schema_version` 3 and carries a `provenance` block with one vocabulary defined in `src/provenance.py`: **dataset** (name, file, target, drop columns, sha256 over the bytes on disk, shape, source pinning), **split** (fold count, seed, train-index sha256, and the fold construction as a `{constructor, params}` rule rather than a description string), **model** (version resolved from `src/model_version.py`, weights sha256, client version) and **code** (git sha, dirty flag, runtime versions, container image). No pilot record has ever carried a model version before, so two pilot numbers from different model eras could not be compared; `weights_sha256` corroborates the version and never substitutes for it. `read_record`/`verdict` turn any record into `comparable`, `partial` or `unusable` and name the missing keys by index (`provenance.model.version`), dispatching on a `schema_version` per record kind and failing closed on an unknown version, an explicit null or a bool rather than guessing; the eight v2 arm records and the four v1 capture manifests are read through their documented pre-block keys and come out `partial` (missing their model version and git sha; missing the dataset and split fingerprints), the records that identify neither come out `unusable`, and none is rewritten. `model.version_source` records that the pilot's version is the resolver's declaration, not a pinned estimator (follow-up #285). `dataset_fingerprint` now takes the frame plus target and drop columns instead of resolving a dataset name, so a second runner can call it, and the pilot adapter records its dataset declaration's drop columns; `analyse_pilot.py` reads schema-3 records unchanged and no committed record under `outputs/` or `results/` is modified. Vocabulary and the version-not-hash decision: `docs/adr/0003-record-contract-and-model-version.md`; *record* and *verdict* added to `GLOSSARY.md`
- feat: one diagnostic record writer — issue #211: the pilot's provenance helpers (`dataset_fingerprint`, `inference_context_rows`, `assert_matched_context`) move into `src/provenance.py` and are imported back by `scripts/run_pilot.py` with identical results; `write_diagnostic_record` is the one writer D1–D5 emit through, with a single field definition (`DiagnosticRecord`), a `schema_version`, one `<diagnostic>/<run_id>/` directory per record holding `record.json` (source of truth) plus `record.csv`, and a **refusal** to replace an existing record, so a stale `csv.DictWriter` header, a split record and a re-stamped old record are structurally impossible. Records carry the resolved model version, seed, dataset fingerprint, runtime versions and the matched-context assertion's evidence, ready for #241's `provenance` block. `scripts/diagnostics/d1_profiling.py` is the first consumer; `outputs/diagnostics/` is git-ignored and D1 exposes no flag that could write elsewhere. Pilot schema stays 2 and no committed record changes
- docs: the paid-run path gets its vocabulary and its spine — ADR `docs/adr/0002-launch-identity-and-the-spend-gate.md` records the three contracts settled on issue #245: a launch id minted before any spend with each run's id derived from it, a spend gate that decides over four pre-spend checks and records a refusal, and the provider CLI as the seam with the mock as its second implementation. `GLOSSARY.md` gains *launch*, *launch id*, *arrival* and *spend gate*; *run* is unchanged. No code changes
- feat: the paid-run path can launch a second seed — issue #263: `vast_run.sh --seeds 42,43` exports `SEEDS` into the generated onstart payload (and into the SSH invocation) and `bootstrap_pilot.sh` forwards `${SEEDS:+--seeds "$SEEDS"}` to `run_pilot.py`, which has accepted `--seeds` since it existed but was never reachable from the launcher — so a two-seed replication (Stage 1 of the funded design) could not be launched at all. No split, threshold or metric changes
- feat: experiment registry — issue #230: the frontier suite's datasets, methods and experiments are declared once in `scripts/eval/insurance_benchmark_v1/experiments.toml`, read by a fail-closed loader (`src/experiment_spec.py`) that refuses unknown keys, an unrecognised schema version, duplicate ids, dangling references and missing fields by name; `run_frontier_benchmark.py --experiment <id>` selects a registered experiment and stamps its id into the run manifest, the capture manifest and every results-CSV row, records the resolved model version, and refuses a `--seed` that contradicts the experiment's declaration. No computation changes: the same command on the pre-change tree gives bit-identical values

## [v8.2.0] — 2026-08-06

Benchmark suite release: TabArena harness, parsimony frontier, lapse settlement, Spanish motor portfolio, regression Phase 2, adoption regime.

### Added
- TabArena benchmark harness + v1 suite: 6 classification + 3 regression insurance datasets, 10 models, 5-fold CV (seed 42), same-fold comparisons — `scripts/eval/insurance_benchmark_v1/`
- Parsimony frontier analysis: accuracy-per-complexity across 12 datasets, per-dataset verdicts — `scripts/eval/` frontier outputs
- Lapse settlement benchmark: eudirectlapse class + regression via TabArena bundle — `scripts/eval/lapse_benchmark_v1/`
- Spanish motor portfolio: frequency, lapse, severity variants + benchmark naming canon (issue #27a)
- Regression Phase 2: RMSE + Poisson-deviance frontiers, 4 datasets (issue #27 D4)
- Home-turf size sweep: 3 datasets × 3 sizes × TabPFN (n8/n1/default) + GBDT baselines — `home_turf_sweep_results.csv`
- Imbalance pilot — `scripts/eval/insurance_imbalance_pilot/`
- Benchmark summary one-pager for actuarial colleagues — `docs/archive/TABPFN_BENCHMARK_SUMMARY.md`
- Regime characterization + adoption guidance (issues #52/#53) — `docs/analyses/regime_characterization.md`
- TabPFN levers assessment: fine-tuning / HPO / ensembling (issue #54)
- Version-drift re-test policy (issue #55)
- `scripts/infra/make_notebook.py` — clone template notebooks (strips outputs) for new experiments
- (earlier, previously unversioned) `LICENSE` (MIT), `CHANGELOG.md`, `tests/` smoke test, wiki + backlog sync tooling

### Changed
- Scripts reorg: active benchmarks → `scripts/benchmarks/`, shared tooling → `scripts/infra/`, legacy fine-tuning → `scripts/legacy_finetuning/` (issue #27)
- Benchmark protocol: single 80/20 split → 5-fold CV; TabPFN `model_path` pinned to `v3_default`
- Replication notebook loads bundled `data/raw/eudirectlapse.csv` first — R/CASdatasets no longer required (fallback retained)
- API key removed from code; `TABPFN_API_KEY` env var with documented setup

### Removed
- Superseded `finish_home_turf_sweep.py` and `STATUS_REPORT_FINAL.md` (superseded by the report registry); `.venv/` artifacts untracked

### Fixed
- `bemtl97` label-leak dataset excluded from frontier results (leak-fixed version used, §6 master report)
- Stale and phantom file references removed across docs (human-voice cleanup, PR #64)
- Colab widget metadata stripped from notebooks

### Headline verdict
TabPFN is a small-data specialist, not a general engine: wins 8/9 size-sweep cells at ≤5K rows and the Spanish lapse + premium-regression cases, but sits off the parsimony frontier 5 of 12 times at scale. Adoption decision rule: `docs/analyses/regime_characterization.md`. One-page summary: `docs/archive/TABPFN_BENCHMARK_SUMMARY.md`.
