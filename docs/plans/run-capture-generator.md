# Plan — one offline command writes a run's capture manifest

**Issue:** #362 (slice of #360; shape decided in #355).
**Status:** Current.

## What and why

A cited run's numbers can lose their bytes and nobody would know (#351). The decided fix is one
versioned `capture.json` per run, written offline over an existing run directory: an entry per
arm × seed carrying the row count and the two array hashes, or null hashes and a reason when an
array was not retained. This ticket builds the generator and nothing else; reading and verifying
the manifest is the rescore slice (#361).

`scripts/analyses/make_capture.py --run results/<run_id>` reads `<run>/<dataset>/<arm>/seed<S>_fold<F>/`,
hashes the arrays, and writes `capture.json` at the run root. Running it over the committed anchor
(`results/20261031T021845Z/uslapseagent`, four arms × two seeds) produces the first real manifest,
which is committed with this change as the positive fixture for the guard in #364.

## Shape

Fixed field set, `schema_version: 1` (the version #355 decided):

```json
{
  "schema_version": 1,
  "run_id": "20261031T021845Z",
  "dataset": "uslapseagent",
  "created_utc": "2026-10-31T02:18:45Z",
  "captures": [
    {"arm": "A_raw", "seed": 43, "rows": 1000,
     "predictions_sha256": "…", "truth_sha256": "…",
     "record": "A_raw/seed43_foldNone/meta.json", "reason": null}
  ]
}
```

Capture entries sort by `(arm, seed)`. Nothing the record already holds is copied: `record` is a
relative pointer to `meta.json`.

## Judgement calls

1. **The hashes cover the array's contiguous bytes, not the `.npy` file's bytes.** The record
   already spells `predictions_sha256` that way (`_sha256_array` in `scripts/run_pilot.py`), and
   #357 requires the manifest and the record to agree when both exist. Measured over all eight
   anchor slots: the record's `predictions_sha256` equals `sha256(np.load(...).tobytes())` in
   every case and never equals the file hash (e.g. `A_raw/seed43` record `1bf20e52…`, file
   `5e69fdde…`). Hashing file bytes would make every manifest disagree with every record.
2. **`created_utc` is the run's start, parsed from the run id — not the generator's clock.**
   "Two runs over the same directory produce byte-identical manifests" is an acceptance
   criterion, and `datetime.now()` would fail it on the second run. The run id *is* a UTC
   timestamp (`20261031T021845Z`), so the manifest is stamped with the run, not the tool.
3. **One dataset per run directory.** The shape carries a single `dataset` field. Zero or more
   than one dataset directory refuses, naming what it found, rather than silently picking one.
4. **A fold-qualified slot other than `seed<S>_foldNone` refuses.** The decided shape has no
   `fold` field, so `seed42_fold0` and `seed42_fold1` would collide on the same arm × seed. This
   slice covers the single-split runs the anchor is; folds would need a shape change decided
   elsewhere.
5. **A slot with arrays but no `meta.json` refuses.** `record` is the manifest's join point and a
   pointer to nothing is worse than a stated failure. An absent *array* is the case the shape
   does carry, and gets null hashes plus a reason naming the file.
6. **`rows`** comes from the predictions array; from the truth array when predictions is missing;
   from the record's `test_rows` when neither array exists.

## Seams under test

The artifact a reader opens: `capture.json` on disk, generated by the CLI over a copy of the
anchor. The test computes each hash independently from the array it loads; it does not call the
generator's helper to produce the expectation.

## Verification

- `pytest tests/test_capture_manifest.py -q`
- `python scripts/analyses/make_capture.py --run results/20261031T021845Z` twice, then
  `git diff --exit-code results/20261031T021845Z/capture.json` — identical bytes.
- The committed manifest is checked against a fresh in-memory build, so it cannot drift from the
  arrays without the suite failing.
- `./scripts/check.sh` (with `EVIDENCE_CHANGE_OK=1` locally: the manifest is a new file under
  `results/`, and the PR carries the `evidence-change` label).

## Out of scope

- Reading or verifying manifests — the rescore slice (#361).
- Native manifest writing by the paid runner — offline by decision.
- Repairs to older runs: forward-only, and the anchor is the only run this writes.
